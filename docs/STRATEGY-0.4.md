# STRATEGY-0.4 · 下一步：先维护，不接新功能

> 基线 2026-11-12（`4b25139` 之后）。依据：GitLab `sheepitrenderfarm/www` 源码（master）+ 本仓库实测数字。
> 上一版 STRATEGY-0.3 的结论（三个高频界面 + 零成本切换）仍然成立；这一版回答「接下来做新功能还是维护」。

## 1. 结论：维护。三条硬证据

| 证据 | 数字 | 含义 |
|---|---|---|
| 功能在涨，覆盖没涨 | 7 个接管视图，`regress` 只覆盖 4 个（overview / projects / ranking / session）；**teams、team 详情、account 零回归断言** | 最近五轮加的东西，全靠手测，改一次就可能悄悄坏 |
| 文档 > 源码 | `docs/` 426KB，`src/` 403KB | 说得多、验得少；文档已经不是资产而是负债 |
| 产物在回涨 | 392KB → **403.9KB**（5 轮 +12KB），注释 21.6% | 减法的成果正在被新功能吃掉，而新功能的验收还没补上 |

判断口径不变：**每加一个视图，就要有它的一条回归断言**。现在欠 3 条，所以先还债。

## 2. 源码给的边界（这次是真的清单）

站点（Symfony）暴露的端点，按我们的接管面分组：

| 域 | 端点数 | 我们接了 | 说明 |
|---|---:|---|---|
| 团队 `/team` | 13 | 7（列表/详情/加/退/解散/申请/移除） | `adduser` / `refuseuser` / `canceljoin` / `update` / `leave_them_new_ownership` 没接 |
| 首页 `/home` | 6 | 2（`/`、`/home`、`/home/projects`） | `machines` / `frames` / `binaries` 未接 |
| 项目 `/project` | 32 | 0（已放行） | 用户创建项目数为 0 → 整域不做 |
| 排行 `/ranking` | 2 | 1（user） | `machine` 未接 |
| 会话 `/session` | 10 | 3（单页/时间线/运行状态） | 其余是日志与重置类，低频 |
| 用户 `/user` | 47 | 8（profile/edit/登录态/优先级/黑名单/赞助/密钥/头像） | `message`、`scheduler` 的 max 档等未接 |

**这张表本身就是结论**：剩下的端点里，真正对「看数据 / 项目列表 / 优先级」有价值的只有 2–3 个，其余是管理端或低频页。继续接是范围蔓延。

## 3. 维护清单（按 ROI 排序，每项带验收）

| # | 动作 | 为什先做这个 | 验收 |
|---|---|---|---|
| 1 | **给团队三个视图补回归**：`teams`（1616 条）、`team`（详情 144 行）、`team` 的 5/6 列形态 | 已上线但零断言，改 CSS 或解析都可能悄悄坏 | `regress` 从 6 case 增到 9 case，页面断言覆盖成员数 / 列数 / 自己那行 / 移除按钮有无 |
| 2 | **移除成员做一次真实验证** | 现在只有「按模板造的假页面」验证过，真按钮长什么样没见过 | 团队里有第二个成员后，创建者视角点一次（或至少读到按钮并确认 URL 形态） |
| 3 | **处理 `74-prefetch.js`（3.8KB）** | 默认关、且 `classicAligned()` 分支在当前架构里几乎没有触发点——留着是死重 | 要么给出真实触发路径并补一条断言，要么删掉（保留 `playInstant` 就够） |
| 4 | **文档减半**：426KB → 200KB 以内 | 文档量已超源码；新人/后来的 AI 读不完就等于没有 | `docs/` 总量 < 200KB，且 STRATEGY/ROADMAP 各留一份当前有效的 |
| 5 | **产物回到 440KB 线内并清死词条**（`mg.*` / `sess.*` 里的动态键） | 减法是这个项目唯一可量化的优势，不能让它回弹 | `build --check` 产物 < 420KB，`check-ui-dict` 式对照无死键 |

## 4. 如果维护做完，新功能只考虑这三个

按「源码里有数据 + 对上用户任务 + 只读低风险」排：

| 序 | 功能 | 源码依据 | 为什么值 |
|---|---|---|---|
| 1 | `/home/frames` 帧记录 | `HomeController::frames` | 用户任务第一条「看自己的贡献」的深挖；数据在同一份页面里，不需要新解析器堆栈 |
| 2 | `/ranking/machine` | `RankingController::machine` | 现有 ranking 视图换个数据源，边际成本最低 |
| 3 | 团队管理剩余动作（`adduser` / `refuseuser` / `canceljoin` / `update`） | `TeamController` 13 个端点已列全 | 团队榜已有，补齐后团队功能才算闭环；但都是写操作，要逐个确认 |

## 5. 明确不做（源码证明不值得）

| 不做 | 依据 |
|---|---|
| 项目 manage 全域（32 个端点） | 用户创建项目数为 0；PRODUCT 已把项目方排除 |
| `/home/binaries`、`/getstarted` 上传链路 | 上游高频改动 + 站点自己渲染，接过来只是负债 |
| `/user/message` 私信 | 站点级 IM，和「看数据」无关 |
| `/session/log` 等日志端点 | 低频，且会话页已经给了按天汇总 |

## 6. 这一版的一句话

**这个项目现在缺的不是功能，是把已经吹过的牛逐个钉上证据。** 三块新界面上线时都是手测通过的，而回归清单里一条都没有——这比少做三个功能危险得多。
